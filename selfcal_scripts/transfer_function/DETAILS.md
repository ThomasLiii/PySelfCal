# Transfer-function kit — details

Background and options behind [`README.md`](README.md).

## Why the injection is just a crop

The pipeline stores each reprojected frame's `sub_data` as the exposure **already
reprojected onto the reference grid**, bbox-cropped to `ref_coords = [y0,y1,x0,x1]`.
So `sub_data` has shape `(y1-y0, x1-x0)` and pixel `(i,j)` corresponds to
reference-grid pixel `(y0+i, x0+j)`. (Verified on a real D3 frame:
`ref_coords=[2422,5574,6421,9573]`, `sub_data` shape `(3152,3152)` — an exact bbox
crop, ~58% NaN = the detector footprint.)

Injecting a fake sky `S` (defined on the detector's reference grid) is therefore
a plain per-frame crop:

```
sub_data_new = S[y0:y1, x0:x1]      # keep NaN wherever the real frame was NaN
```

Preserving the original NaN pattern keeps each frame's **observed footprint**
identical to the fiducial run — only the sky values change, not the coverage.
`inject_fake_sky.py` copies every frame whole (so `sub_mapping`, `sub_bitmask`,
`sub_foot`, `ref_coords`, WCS headers, and the **filename** are unchanged) and
overwrites only `sub_data`. Because the filenames are kept, the `exp_<n>_det_<n>.h5`
indices still parse, and the SPHEREx LVF geometry (chunk maps, per-pixel
wavelengths) that the runner rebuilds from `detector=N` still lines up.

The frames are **Zstd-compressed HDF5**, so any code that reads/writes them must
`import hdf5plugin` (a `selfcal` dependency). The kit scripts do.

## What the runner supplies automatically

You provide only the frames, the `ref.fits`, and the fake sky. You do **not**
provide chunk maps, valid masks, or wavelengths — the SPHEREx instrument adapter
rebuilds those from `detector=N` plus the LVF parameters shipped inside the
package (`selfcal/instruments/spherex/data/lvf_params/`).

## The fiducial recipe

`transfer_function.toml` holds the frozen fiducial continuum recipe — the same
one behind the fiducial D1–D6 mosaics (from `selfcal_scripts/configs/d5.toml`):

- `mode = "continuum"`, `oversample = 2`, `num_col = 10`
- `[params]` `poly_degree = 1`, `poly_weight = 0.5`, `reg_weight = 0.1`
- `[calibration]` `outlier_thresh = 5`, `weighted_damping = true`,
  `damp_weight = 0.1`, `offset_regularization = true`
- `[lsqr]` `iter_lim = 50`, `precondition = true`, `solver = "lsqr"`, `atol=btol=1e-6`
- `[mosaic]` `sigma = 2`, `apply_sigma_clipping = true`, `make_std_map = true`

You do not edit this file for normal use — `run_transfer_function.sh` fills in the
six run-specific fields. Edit it only to deliberately deviate from the fiducial.

## Channels

Each SPHEREx detector is a linear variable filter split into 34 spectral channels
(`num_ch = 34`); each channel is an independent calibration + mosaic at its
wavelength. The kit runs a **single** channel (default the mid-band `Ch17`, via
`channels = [[N]]`) — enough to characterize the transfer function without 34× the
compute. Valid channel indices are 1..34; pick with `--channel N`.

## The six inputs and three ways to set them

`run_transfer_function.sh` exposes exactly six inputs and hides everything else
(the recipe, and pointing the runner at your `ref.fits`):

| input | flag | env var |
| --- | --- | --- |
| detector (1..6) | `-d`, `--detector` | `DETECTOR` |
| channel (1..34) | `-c`, `--channel` | `CHANNEL` |
| fake-sky frames dir | `-f`, `--frames` | `REPROJ_FRAME_DIR` |
| ref.fits | `-r`, `--ref` | `REF_FITS` |
| output dir | `-o`, `--output-dir` | `OUTPUT_DIR` |
| run name | `-n`, `--run-name` | `RUN_NAME` |

Three equivalent ways to pass them (**precedence: flag > env var > default**):

1. **Flags** (see README).
2. **Env vars**, e.g. a loop over detectors:
   ```bash
   for d in 1 2 3 4 5 6; do
     DETECTOR=$d REPROJ_FRAME_DIR=/scratch/tf/D${d}_fakesky_frames \
     REF_FITS=/path/to/D${d}/ref.fits RUN_NAME=TF_D${d} \
     selfcal_scripts/transfer_function/run_transfer_function.sh
   done
   ```
3. **Edit the six defaults** at the top of `run_transfer_function.sh`, then run it
   with no arguments.

`SELFCAL_PY` selects the interpreter (defaults to `python`); set it to your env's
Python if `python` is not the one you installed into.

## How `ref.fits` is wired

The runner reads the reference grid from `{output_dir}/{run_name}/ref.fits`. The
launcher creates that path and symlinks your `--ref` file into it (the file is not
copied or modified). If you invoke the underlying config directly instead of the
launcher, make that symlink yourself.

## Files

- `inject_fake_sky.py` — replace each frame's `sub_data` with the fake-sky crop
  (footprint preserved); parallel over frames.
- `verify_frame.py` — schema + injection sanity check on one frame (with `--orig`,
  confirms only `sub_data` changed).
- `run_transfer_function.sh` — the six-input launcher (symlink `ref.fits`, fill the
  config, run).
- `transfer_function.toml` — the frozen fiducial recipe.
